# 로고체 모션·인터랙션 — 레퍼런스와 판단 (11/6)

코드로 옮기기 전에 움직임을 어떻게 정할지 정리했어요. 지금 코드(globals.css)에는 작은 등장 모션(ds-pop · ds-rise · ds-fade · ds-indeterminate · ds-ants)과 움직임 줄이기 설정(prefers-reduced-motion)이 있어요. 아래는 그 위에 더할 것과 뺄 것이에요.

> 정정(11/6 오후): 처음에 '메인 화면 묶음 전환(document.startViewTransition)이 이미 있다'고 적었는데, 확인해 보니 11/5 메인 재작업 때 그 코드는 빠지고 globals.css의 `::view-transition-*` 규칙(group-0~2)만 남아 있어요. 지금 화면 전환 코드는 하나도 없어요.

## 1. 보통 어떻게 정하나 — 레퍼런스

### 시간과 가속 곡선은 '토큰'으로 정해요
- **Material Design 3**: 짧은 50~200ms(작은 기능 전환), 중간 250~400ms(화면의 중간 넓이를 가로지르는 전환), 긴 450~600ms(크게 펼쳐지는 전환), 아주 긴 700~1000ms(사용자 입력이 없는 배경 전환, 드묾).
  - 곡선: 표준 `cubic-bezier(0.2, 0, 0, 1)`, 들어올 때(감속) `cubic-bezier(0.05, 0.7, 0.1, 1)`, 나갈 때(가속) `cubic-bezier(0.3, 0, 0.8, 0.15)`.
  - 참고: M3 Expressive부터 부품 움직임은 스프링 물리로 옮겼고, 시간·곡선 체계는 화면 전환용으로만 남았어요.
- **NN/g**: 체크박스·토글 같은 단순한 반응은 약 100ms, 창이 열리는 정도의 변화는 200~300ms, 전체로는 100~400ms. 500ms 근처부터는 굼뜨게 느껴져요.
  - 나타날 때가 사라질 때보다 조금 길어요(예: 열림 300 / 닫힘 200~250).
  - 자주 반복되는 움직임일수록 짧고 은은하게. "너무 짧은 것보다 너무 긴 경우가 훨씬 흔하다."

### 접근성 기준이 '무엇을 빼야 하는지'를 정해요
- **WCAG 2.2.2 일시 정지·정지·숨기기(A 등급, 필수)**: 저절로 시작해서 5초 넘게 다른 내용과 함께 움직이는 것은 멈추거나 숨길 수단이 있어야 해요. 다만 로딩 중이라 아무것도 할 수 없는 동안의 로딩 표시는 '필수'라 예외예요.
- **WCAG 2.3.3 상호작용에서 생기는 움직임(AAA)**: 사용자가 일으킨 움직임은 움직임 줄이기 설정을 켜면 끌 수 있어야 해요.
- 움직임 줄이기 설정을 켰을 때 움직임을 실제로 없앤다면, 대부분의 경우 2.2.2의 '멈출 수단'으로도 볼 수 있다는 해석이 있어요. 다만 설정을 켠 사람만 혜택을 받아요.

### 팀에서 정리하는 방식
- 디자인 시스템 문서(DESIGN.md)에 **모션 토큰**(시간·곡선 몇 개)을 두고, 화면마다 **모션 표**(무엇이 · 언제 · 무엇을 · 몇 ms · 어떤 곡선 · 움직임 줄이기에서는 어떻게)를 적어요.
- 핵심 한두 개만 시제품(영상·프로토타입)으로 보여 주고, 나머지는 표로 넘기는 게 흔해요.

## 2. 판단

| 아이디어 | 판단 | 이유 |
|---|---|---|
| 민트 바탕 뒤 패턴·흐르는 효과 | **뺌** | 민트 면은 '지금 맡기는 중 / 일하는 중'을 알리는 단색 신호라, 패턴이 생기면 신호가 흐려지고 접수 화면에서는 입력 칸과 시선을 다퉈요. 흐르는 효과는 저절로 5초 넘게 움직이는 병행 콘텐츠라 WCAG 2.2.2의 멈춤 수단이 필요하고, 만드는 중 화면은 12~17분 머무는 화면이라 가장 오래 노출돼요. 만드는 중에는 이미 진짜 정보가 움직여요(막대·방금 그린 글자). 장식보다 실제 일이 움직이는 게 기다림을 덜 지루하게 해요(노동 착시). |
| 스티커 반짝임(포켓몬 카드 홀로) | **일부만** | '완성' 도장 하나에만, 완성 띠가 처음 열릴 때 빛이 한 번 훑고 지나가요(약 600ms, 끝나면 멈춤). 데스크톱에서 마우스를 올리면 빛 각도가 포인터를 따라가요. 번호표·말풍선·2,350자 스티커에는 쓰지 않아요. 한 곳에만 있어야 '완성'이 보상처럼 느껴져요. 모바일 기울기 센서는 iOS에서 권한 요청이 떠서 쓰지 않고, 처음 한 번 훑기만 해요. 구현은 pokemon-cards-css처럼 CSS 변환·그라디언트·블렌드 모드 한 겹(라이브러리 없음). 요소가 하나라 부담이 적어요. |
| 스티커 둥실둥실 떠다님 | **뺌 → '붙는 순간' 한 번으로 → 11/6 밤: 완성 도장에만** | 계속 반복되는 움직임은 입력하고 읽는 동안 시선을 끌고, 메인 말풍선은 입력 칸 바로 옆이에요. '붙는' 모션(살짝 크게 1.06배·기울기 −2°에서 제자리로 240ms 감속)은 **스튜디오 첫 방문의 완성 도장에만** 남겨요. 번호표·말풍선·별 터짐은 처음부터 붙어 있어요(11/6 밤 결정: 아무 사실도 바뀌지 않는데 움직이는 건 장식이에요). |
| 버튼 눌렀을 때 화면 넘어가는 모션 | **넣음(제한적, '들어오는 쪽만')** | 원칙은 '같은 물건이 이어지면 이어서 보여 주기'예요. 접수증·번호표처럼 화면을 넘어가도 계속 있는 물건은 움직이지 않고, 바뀌는 안쪽 내용만 들어오는 모션을 줘요. 질문 단계는 주소가 바뀌는 페이지 이동(`/make/[step]`, router.push)이라 View Transitions로 이으려면 Next.js의 실험 기능이 필요해요(공식 문서상 운영 비추천). 그래서 화면 전환 API 대신 '새 내용이 들어올 때 한 번' CSS 모션으로 해요. 나가는 모션은 생략해도 어색하지 않고, 지원 브라우저 걱정도 없어요. |

### 화면 전환 — 어디에 무엇을
- **질문 1/4 → 4/4**: 접수증 카드 틀은 움직이지 않고, 안쪽 질문 내용만 들어와요(200ms, 아래에서 6px 올라오며 나타남). '지금까지 접수한 것' 줄에 새로 붙는 체크만 톡(100ms).
- **로고 권리 → 로고 읽는 중**: 같은 방식으로 윗부분 내용만 들어와요.
- **확인 창 '만들기 시작' → 만드는 중**: 확인 창은 200ms로 닫혀요. 만드는 중 화면의 번호표는 움직이지 않고 그냥 있어요(11/6 밤: '붙기' 뺌). 남은 시간이 바뀔 때만 숫자가 넘어가요.
- **만드는 중 → 완성**: 같은 페이지 안에서 단계가 바뀌는 것(FontView의 phase)이라 완성 띠가 들어오고, 완성 도장이 붙은 뒤 반짝임이 한 번 지나가요.
  - **언제 재생하나**: 완성 '순간'에만. 만드는 중 화면을 보다가 완성으로 바뀐 경우, 또는 완성 뒤 처음 이 폰트를 연 경우(브라우저에 '봤음' 표시를 남김, 못 읽으면 그냥 재생). 다시 들어올 때마다 반짝이면 보상이 아니라 장식이 돼요.
- **나머지 페이지 이동(내 폰트 ↔ 스튜디오 등)**: 모션 없음. 매번 보는 이동이라 빠른 게 나아요.
- **뒤로 가기**: 들어오는 모션 그대로(방향을 따로 구분하지 않아요).

### 그 밖에 넣을 것(작은 반응)
- **버튼 누름**: 눌린 순간 0.97배로 100ms. B3는 마우스를 올리면 민트 동그라미 안 화살표가 오른쪽으로 2px.
- **고르기**(3/4 칸, 견본 카드, 다시 볼 글자): 체크 원이 150ms로 톡 나타남. 질문 칩·글자 다듬기 프리셋에는 체크가 없어요(11/6 밤). 고를 때 칩·칸의 크기와 자리는 그대로(색·테두리·굵기만 바뀜).
- **진행**: 막대 너비는 300ms로 부드럽게. (글자 지도 칸 전환은 11/6 저녁 지도 삭제로 없어요.) 방금 그린 글자는 지금 있는 ds-pop(260ms) 그대로.
- **번호표 남은 시간**: 숫자가 바뀔 때 세로로 넘어가는 모션 200ms(바뀐 걸 알아채게).
- **아래 창·서랍**: 열림 300ms 들어오는 곡선, 닫힘 200ms 나가는 곡선. 떠오르는 막대는 아래에서 8px 올라오며 200ms.
- **같은 화면 안 이동**(11/6 밤): 머리 줄 '만드는 법' → 만드는 순서, 마무리 띠 '접수증으로 올라가기' → 접수증은 브라우저 부드러운 스크롤(`scrollIntoView({behavior:'smooth'})`). 움직임 줄이기면 바로 이동. 접수증으로 올라가면 첫 칸(로고 올리기)에 초점.

### 뺄 것
- 스크롤에 따라 움직이는 패럴랙스, 커서를 따라다니는 효과, 숫자가 올라가는 카운트업(남은 시간이나 글자 수가 실제와 다르게 보이는 순간이 생김), 완성 축하 꽃가루(도장 반짝임 하나로 충분), 로딩 뼈대가 번쩍이는 효과(지금처럼 '그리는 중' 돌기 표시 유지).

## 3. 토큰 제안 (DESIGN.md에 넣을 것)
| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--dur-fast` | 100ms | 버튼 누름, 체크 |
| `--dur-base` | 200ms | 질문 내용 들어오기, 닫힘, 숫자 넘김, 떠오르는 막대 |
| `--dur-move` | 300ms | 막대 너비, 아래 창·서랍 열림 |
| `--dur-moment` | 600ms | 완성 도장 반짝임 한 번(여기에만) |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 기본 |
| `--ease-enter` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 나타나기·열기 |
| `--ease-exit` | `cubic-bezier(0.3, 0, 0.8, 0.15)` | 사라지기·닫기 |
- 지금 코드의 ds-pop 260ms · 160ms, ds-rise 160ms는 각각 `--dur-move`(만드는 중 글자) · `--dur-base`(메뉴·떠오르는 막대)로 맞춰요.
- 남아 있는 `::view-transition-*`(group-0~2) 규칙은 쓰는 곳이 없어 지워요.
- **움직임 줄이기**: 옮겨 가거나 커지는 움직임(변환)은 끄고, 색·투명도 변화만 남겨요. 반짝임은 멈춘 그림으로. '그리는 중' 돌기 표시는 지금처럼 천천히 남겨요(로딩 표시는 필수 예외).

### 구현할 때 지킬 것
- 움직이는 건 위치·크기·투명도(transform · opacity)만. 너비가 바뀌는 진행 막대도 가능하면 scaleX로.
- 마우스를 올렸을 때만 생기는 효과(B3 화살표, 도장 빛 따라가기)는 마우스가 있는 기기에서만(`hover: hover`). 휴대폰에서 눌렀을 때 효과가 남아 있지 않게요.
- 만드는 중 화면의 로딩 표시(로고 깜빡임, 막대 왕복, 돌기)는 '로딩 표시'라 WCAG 예외예요. 그대로 두되 지금처럼 움직임 줄이기에서는 멈추거나 느리게.

## Claude Code로 넘길 때
코드는 채팅에 쓰지 않고 이 절을 그대로 넘겨요.
1. globals.css: 위 토큰 7개를 CSS 변수로 추가. 쓰지 않는 `::view-transition-*`(group-0~2) 규칙 삭제. 지금 ds-pop · ds-rise 시간을 토큰으로 바꾸기.
2. 새 키프레임 두 개: '붙기'(1.06배·−2° → 1배·원래 각도, 240ms, ease-enter — 11/6 밤부터 완성 도장에만), '빛 한 번 지나가기'(완성 도장 위 비스듬한 밝은 띠, 600ms, 한 번).
3. MakeWizard.tsx: 단계가 바뀔 때 접수증 안쪽 내용 묶음만 들어오는 모션(200ms, 6px 위로). 새로 생긴 체크만 톡. 접수증 틀·머리줄·버튼 줄은 움직이지 않기.
4. Making.tsx: 남은 시간 숫자가 바뀔 때 세로로 넘어가기 200ms. 진행 막대 채움 300ms 부드럽게. (번호표 '붙기'는 11/6 밤에 뺌, 지도 칸 전환은 11/6 저녁 지도 삭제로 뺌)
5. Studio.tsx: 완성 도장 '붙기' → '빛 한 번'. 재생 조건은 위 '언제 재생하나'. 데스크톱(마우스)에서만 마우스 위치에 따라 빛 각도가 따라오기. 도장 말고 다른 스티커엔 넣지 않기.
6. 메인 말풍선·번호표·별 터짐 스티커: 움직이지 않기(11/6 밤: '붙기'도 뺌). 계속 움직이는 모션도 넣지 않기.
7. 공통 작은 반응: 버튼 눌림 0.97배 100ms. B3 마우스 올림 시 화살표 오른쪽 2px. 고르기(3/4 칸·견본 카드·다시 볼 글자) 체크 원 150ms 톡 — 칩에는 체크 없음(11/6 밤). 아래 창·서랍 열림 300ms(ease-enter) · 닫힘 200ms(ease-exit).
8. 움직임 줄이기: 위치·크기 변화는 끄고 투명도·색만. 반짝임은 멈춘 그림. 로딩 표시는 지금 규칙 유지.
9. 하지 않을 것: 민트 바탕 패턴·흐름, 스티커 둥실둥실, 패럴랙스, 커서 따라다니기, 카운트업, 꽃가루, Next.js `experimental.viewTransition`.

## 구현 뒤 확인 (문서가 아니라 실제 화면으로)
모션은 글로 검증이 안 돼서, 레퍼런스를 더 모으기보다 만든 뒤에 아래만 확인해요.
1. 크롬 개발자 도구 Animations 패널에서 10% 속도로 재생: 시간·곡선이 표대로인지, 나가는 쪽이 들어오는 쪽보다 짧은지.
2. 운영체제 '동작 줄이기'를 켜고 질문 → 만드는 중 → 완성을 한 번 지나가기: 위치·크기 움직임이 다 꺼지고 반짝임이 멈춘 그림인지.
3. 중저가 안드로이드 폰에서 만드는 중 화면(글자 칸이 계속 붙는 화면)과 완성 반짝임: 끊김 없는지, 레이아웃이 밀리지 않는지(Performance 패널의 Layout Shift).
4. 5초 넘게 저절로 움직이는 게 로딩 표시 말고는 없는지.
5. 완성 반짝임이 두 번째 방문에는 안 나오는지.

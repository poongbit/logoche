## 11/6 오후 피드백 — 판단과 반영
- **가게 이야기 최소 글자 수 → 10자로 막고, 30자 아래는 부드럽게 권하기**
  - 프롬프트가 가게 이야기만 보는 게 아니에요. 업종·쓸 곳 칩·분위기 칩(최대 3)·글씨 취향 네 쌍·로고 그림이 같이 들어가요. 가게 이야기가 맡는 건 '무엇을 파는 어떤 가게인지'와 AI가 쓰는 문장(slogans)·이유(why)의 재료예요.
  - 10자('칼국수 파는 집이에요')면 무엇을 파는지는 들어가요. 18자로 올려도 '무엇을' 위에 '어떤 가게로'가 붙는다는 보장은 없어요. 글자 수는 내용의 대리값일 뿐이라, 문턱을 높이면 내용보다 숫자를 채우게 돼요.
  - 그래서 막는 선은 10자(코드 그대로)로 두고, 10~29자에는 막지 않는 안내 '어떤 가게로 기억되고 싶은지 한 줄 더 적으면 더 잘 맞아요'를 보여요. 예시 문장(placeholder)이 두 문장 길이라 기대 분량은 거기서 전해요.
  - 시안의 '18자'는 모두 '10자'로 고쳤어요.
- **메인 '예시' 꼬리표를 민트로?** → 권하지 않아요(16 페이지 비교판 ①).
  - 알약 모양 민트는 흰 바탕에서 누르는 버튼이나 '새것·추천' 배지로 읽혀요. 이 꼬리표는 '이건 예시'라는 단서라 강조될 이유가 약하고, 흰 바탕 민트 버튼 금지 규칙과도 부딪혀요.
  - 민트를 꼭 쓰고 싶다면 알약 대신 **민트 형광펜**(첫 화면 흰 형광펜과 같은 장치)이 버튼처럼 안 보여요. 비교판 세 번째.
- **'쓸 수 있는 범위' 메인·스튜디오 둘 다?** → 둘 다 두되 깊이를 달리해요.
  - 메인: 만들기 전에 결정하는 자리라 '독점이 아니다'를 미리 알아야 해요. 세 줄 요약 + 전문 링크(비교판 C).
  - 스튜디오: 실제로 받아 쓰는 자리라 전문(비교판 B 줄 표)을 받기 바로 아래에. (11/6 저녁: 받기 섹션을 지우고 '글자와 검사' 아래로)
  - 지금처럼 같은 회색 상자를 두 번 쓰는 건 중복이에요.
- **'쓸 수 있는 범위' 디자인** → 회색 상자 세 칸(A)은 칸마다 내용 길이가 달라 기울고, 페이지에서 유일한 회색 상자라 문법이 어긋나요. B(1px 먹 줄 표 + 그린 표시 ✓ × !)와 C(한 줄 요약)를 그렸어요.
- **ST2 써 보기 문구를 질문 답으로 채울 수 있나** → 이미 반쯤 돼 있어요.
  - 서버가 로고를 읽을 때 가게에 맞는 짧은 문장 3개(`slogans`, 12~20자, 폰트에 있는 글자만 걸러 냄)를 만들고, 스튜디오가 이미 써요(Studio.tsx).
  - 가격표 줄은 AI가 아니라 업종별 고정 메뉴(`MENU_BY_INDUSTRY`)예요. 업종을 직접 쓴 가게는 '분식' 메뉴로 떨어져서 엉뚱할 수 있어요 → 이 경우 숫자 줄(영업시간·전화)로 바꿔요.
  - 안내문 줄의 코드 기본 문장 '매일 아침 직접 만든 재료로 정성껏 준비합니다…'는 지어낸 사실이라 빼고 slogans만 써요.
  - ST2 v2: 간판=가게 이름, 가격표=업종 예시 메뉴, 안내문=slogans, 줄마다 출처를 작게. 견본 카드의 지어낸 메뉴도 slogans로 바꿨어요.
- **검은 간판판이 무겁다** → ST2 v2는 회색 판 + 먹 글자(견본 칸 문법). 색은 '더 자세히 써 보기'에서 로고 색으로 바꿀 수 있게. 메인 (b)의 냥이네체 간판도 같은 처리를 권해요(정하시면 반영).
- **ST2 제목 흰 형광펜 · 완성 도장** → v2에 반영. 도장은 카드 안쪽으로 넣고 그림자.
- **L2 다듬기** → L2 v2. '폰트 이름 | 상태' 글자, 줄마다 글자 링크 + 화살표 하나, 번호표 뺌, 견본 칸 이름 가운데, 모바일 설명 8px 들임.
  - 필터: 줄의 알약이 사라져서 밑줄 탭만으로 구분돼요(추천). 민트 채움 필터도 비교로 그렸지만 흰 바탕 민트 버튼 규칙과 부딪혀요.
- **S2는 v2로 가나?** → 네. S1~S4는 한 화면의 상태라 v2 묶음 전체가 추천안이에요.
  - S3 아래에 검사 7항목 줄 표를 그렸어요(코드 CHECKS 일곱 개를 사장님 말로 풀어 씀, 통과·검사 중·기다리는 중).
  - 막대가 끝까지 차면 민트 면 위에서 빈 막대처럼 보여서(먹 테두리만 남음), 글자를 다 그린 S3·S4에서는 막대를 빼고 '글자 2,432자 다 그렸어요' + 단계 줄만 둬요. DESIGN 2-2는 그대로.
- ~~**글자 지도 1자 1칸은 의도?**~~ (11/6 저녁: 글자 지도 삭제) → 데스크톱은 의도(2,350칸이 차는 양 자체가 일하는 모습). 모바일은 6px라 소음에 가까워서 **1장(30자) 1칸**을 제안해요.
  - 서버가 사전 순서대로 30자씩 한 장으로 그려서(rest.ts chunk) 장 단위가 사실과 맞아요. 칸 안에 그 장의 첫 글자, 지금 그리는 8장은 점선. 비교판은 17 페이지 '글자 지도 단위 비교'.
- **다시 그리기 고른 칸** → '다시' 꼬리표 대신 오른쪽 위 먹 체크 원(C1 카드·3/4 후보와 같은 표시). 민트 채움은 글자 그림 뒤 바탕이 바뀌어 모양 판단을 방해해서 쓰지 않았어요.
- **2/4 고른 칩** → 고른 칩을 먹 채움 + 흰 글자로 바꿨어요(전에는 테두리 굵기 차이뿐). 안 고른 칩은 옅은 테두리 + 보통 굵기.
- **3/4 칸** → 후보 A(가게 이름 네 자로 폭 채우기)와 B(두 칸을 한 줄로 붙인 양쪽 고르기, 고른 쪽 먹 채움). **B 추천**: 네 쌍이 모두 반대말이라 '둘 중 하나'가 모양으로 보이고, 2/4의 고른 칩과 같은 문법이에요.

- **3/4 칸 문구 '우리 가게'**: 네 쌍을 같은 낱말로 비교해야 속성 차이만 보여요.
  - 획 끝은 ㄱ·ㅔ의 끝, 굵기 차이는 '우·리'의 가로·세로 획, 손맛은 네 글자가 이어질 때 고르지 않음이 드러나요. '가'(지금 코드) 한 글자는 굵기 차이·손맛이 잘 안 보여요.
  - '가나다'는 견본으로 익숙하지만 뜻이 없고, '우리 가게'는 사장님 자리에서 읽혀요.
  - 가게 이름을 넣는 안은 거름: 칸마다 웹 글꼴을 불러야 하고, 대신 쓰는 글꼴 모양이 완성 폰트처럼 읽힐 위험이 커요.
  - 코드는 고정 그림이라 선택지 8개 × '우리 가게' 4자 = 외곽선 32개를 한 번 만들어 넣으면 돼요.

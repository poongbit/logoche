## 중요: 이 실행은 한 번 끊겼다

도구 점검 중 이 폰트 작업 단계에는 적용되지 않아 **실제 호출이 나갔다**. 약 40초 뒤 알아채고 서버를 껐다(그때까지 그린 글자 959자). 이어서 만들기(서비스에 원래 있는 기능, 그린 글자는 재사용)로 나머지를 이었다. 그래서:

- 비용·호출 수는 두 구간을 합친 값이고, 낭비된 호출은 없다.
- **재시도 전 실패 글자 수**는 이어서 만든 구간(B)에서만 정확히 잰다. 앞 구간(A)은 끊겨서 라운드 기록이 없다.
- 단계별 시간도 나머지 글자 그리기는 A(약 77초, 끊길 때까지)와 B(209초)를 더했다. 재시작에 걸린 사람 쪽 대기 시간은 뺐다.

## 3. 실패와 재시도

| 항목 | 값 |
|---|---|
| 1바퀴 뒤 떨어진 글자(구간 B) | 366자 / 1,391자 = **26%** |
| 2바퀴 뒤 | 109자 |
| 3바퀴(마지막) 뒤 | 92자 |

- 떨어진 이유는 두 가지가 섞여 있다. ① OpenAI 429(속도 제한)로 글자표 한 장 전체가 실패한 경우(로그에 글자표 실패 9회) ② 검사에서 반복해서 떨어진 어려운 짜임. 1바퀴의 366자 중 상당수는 ①이고, 3바퀴까지 남은 글자는 대부분 ②다(뛔·쫴·곌·곕·꼍·삥·뱐처럼 같은 글자가 계속 남음). 이 둘은 서버 로그(구간 B)로 나눠 볼 수 있었다. **429는 1바퀴에만 8건**(글자표 47장 중 8장, 최대 약 240자), 2·3바퀴는 0건이다. 그래서 **최종 빠진 한글 83자는 429 탓이 아니라 검사에서 반복해 떨어진 것**이다. 떨어진 이유는 대부분 "'X'로 읽힘"이다(`docs/missing-83-review.png`). 구간 A는 로그가 없어 세지 못했다. 이 뒤로는 `sheet`·`image_error` 줄로 원인별 글자 수를 기록한다.
- **숫자 0~8이 전부 빠졌다.** 세 바퀴 모두 "다른 글자 섞임"으로 떨어졌고 9만 통과했다. 숫자 한 장이 통째로 체계적으로 실패한 것이라 우연이 아니다. 검사 모음 그림의 칸 번호(1~9)가 칸 안의 숫자(0~8)와 헷갈렸다는 가설을 세워, 기준 서체로 만든 정상 숫자 장을 Claude 검사에 넣어 봤다(번호 방식 두 가지, 각 1회). **둘 다 전부 통과해 가설은 확인되지 않았다.** 원인은 아직 모른다(그린 숫자 그림이 저장되지 않아 직접 볼 수 없었다). 칸 번호는 '#1' 형식으로 바꿔 두었다.
- 스타일 이상치 감지는 이번에 **한 번도 걸리지 않았다.** 남긴 그림의 획 두께·크기 편차(기준 1 대비): 중앙값 2.7%, 95% 7.7%, 최대 20%(로그 0.182 = 임계값). 이 로고는 한 벌이 고르게 나와서였을 수 있고, 감지가 약하다는 뜻일 수도 있다. 다른 로고로도 재야 판단할 수 있다.

## 6. 추가: 빠진 글자만 다시 그리기 (같은 날, 같은 작업)

빠진 한글 83자와 숫자 0~8을 `이어서 만들기`(빠진 글자만 다시 그리기)로 한 번 더 돌렸다. 비용 상한은 3달러로 걸었고 호출 기록은 `docs/full-run-20261103-redraw-ledger.jsonl`에 따로 남겼다(앞 기록과 합산하지 않음).

| 항목 | 값 |
|---|---|
| 다시 그린 대상 | 한글 83자 + 숫자 9자(0~8) = 92자 |
| 채운 글자 | **한글 9자(굵닒륑붊삥쾀퇀휙흴), 숫자 2자(2, 3)** = 11자 |
| 끝내 못 채운 글자 | 한글 74자 + 숫자 0·1·4·5·6·7·8 = 81자 |
| 이미지 호출 | 12회(글자표 4장 × 3바퀴), 어림 약 $0.60 (입력 48,286·출력 7,794 토큰) |
| Claude 호출 | 13회(검사 12 + 판독 1), 입력 33,604·출력 18,302 토큰 |
| 429 | **0건**, 글자표 그리기 실패도 0건 |
| 소요 | 약 157초 |

바퀴별로 떨어진 글자는 85 → 81 → 81자였다. 3바퀴 모두 떨어진 이유는 **전부 검사 탈락**(그리기 실패·엔진 문제 0)이었다.

### 원인을 찾은 것

1. **숫자 0~8이 떨어진 원인은 검사가 아니라 그림이었다.** 이번에 처음으로 떨어진 그림이 남았다(`docs/missing-digits-rejected.png`). 이미지 모델이 칸 번호와 숫자를 붙여 쓴 지시문(`1.0 2.1 3.2 …`)을 소수·분수로 읽어서, 0 칸에 "1", 1 칸에 점, 5 칸에 위아래로 쌓은 "2/3", 7 칸에 "1/4"를 그렸다. 검사의 "5가 아닌 23으로 보임" 같은 판정은 정확했다. 칸 번호 가설(앞 절)은 틀렸고, 이 가설이 맞다. 지시문을 `N번 칸 '기호'`로 바꾸고 "번호나 분수를 그리지 말라"를 더했다. **고친 뒤 다시 그려 보지는 않았다.**
2. **빠진 한글 74자도 검사 오판이 아니라 그림이 틀린 경우가 많아 보인다**(`docs/missing-review-drawings.png`, 실제 그림 + 읽힌 글자). 이미지 모델이 비슷하지만 다른 글자를 그린 것으로 보인다. 예: 뛔를 뛰로, 쫴를 쬐로 그렸다(겹모음의 한 요소가 빠짐). 74자를 하나하나 대조한 것은 아니고 훑어본 인상이다. 사람이 직접 보고 판단해야 한다.
3. 따라서 같은 방식으로 더 돌려도 이 글자들은 채워지지 않을 가능성이 크다. 한 글자씩 다시 그리기나 참고 이미지(기준 글자표) 강조 같은 다른 접근이 필요하다.

# 구조 참고 폰트: 후보 풀과 선택 규칙 초안 (11/5)

도감(`docs/font-catalog-draft-20261105.md`)에서 시트를 눈으로 보고 24종을 골라 `engine/compare/guide_pool.json`에 태그와 함께 두었다. 굵기·느슨함·읽힘·분위기 태그는 **시트를 보고 내 눈으로 붙인 값**이며 아직 시험으로 검증하지 않았다(읽힘 1~3은 특히 거칠다).

## 1. 후보 풀 구성
- 정형 4종(Pretendard, 나눔명조, 주아, 블랙한산스), 구조가 다른 굵은 계열 3종(베이글팻원, 독도, 스타일리시), 나머지 17종은 나눔손글씨 계열(묶음 1·2·4·5·8·9·10·12·13·14에서 1~2종).
- 묶음 3(베이글·가솔)과 묶음 7(굵은 디스플레이)은 폰트가 적어 대표를 1개씩만 뒀다. 묶음 11은 도감에서 비었다.
- 붓 느낌이 강한 `NanumBrushScript`는 사용자가 "붓 느낌 원치 않음"이라고 했으므로 **기본 후보에서 제외**하고, 손맛 "손으로 쓴 듯"을 골랐을 때만 허용한다.

## 2. 라이선스 확인(네이버 글꼴)
hangeul.naver.com/font 안내문 기준(2026-11-05 확인):
- "개인 및 기업 사용자 모두에게 무료, 글꼴 자체를 유료로 판매하는 것을 제외한 상업적 사용 가능", "수정·재배포 자유", "클로바 나눔손글씨도 같은 오픈 라이선스".
- 우리는 폰트 파일을 쓰지 않고 **뼈대 위치만 참고해 새로 그린다**. 파생·재배포가 아니라 참고라서 허용 범위로 보이지만, "글꼴 자체를 판매"에 우리가 만든 폰트 판매가 걸릴 여지는 **법적 판단이 필요**하다(전문 확인 또는 네이버 문의). 이 확인 전에는 서비스 반영이 아니라 시험까지만 한다.
- Google Fonts 폰트(감자꽃·독도 등)는 OFL이다. OFL은 파생물 이름 제한이 있지만 참고용으로 쓰는 것은 문제가 적다. 이 역시 최종 확인 필요.

## 3. 선택 규칙(A안 점수표)
점수 = 분위기 적합 + 쓸 곳 적합 + 손맛 적합. 가장 높은 5개에서 프로젝트 번호로 하나를 랜덤 선택하고(재시도하면 다음 번호), C안은 최근 사용이 많은 묶음 가중치를 낮춘다.

### 분위기(최대 3개 선택) → 폰트 태그 가산점
| 분위기 | + (가산) | − (감점) |
|---|---|---|
| 귀여운 | 둥근·굵은 귀여움 태그, 느슨 | 정형 고딕·명조 |
| 따뜻한 | 따뜻한·친근한 태그, 손글씨 | 블랙한산스 |
| 장난스러운 | 장난스러운·개성있는, 느슨 | 정형 |
| 고급스러운 | 우아한·고급스러운, 가는 굵기 | 굵은·느슨 |
| 믿음직한 | 단정·신뢰, 정형·보통 | 매우 느슨 |
| 전통적인 | 전통적인, 나눔명조 | 현대적 |
| 모던한 | 현대적, 정형·단정 | 장식적 |
| 자연스러운 | 편안한·따뜻한, 보통 느슨 | 굵은 디스플레이 |
| 레트로한 | 빈티지·장식적 | 현대적 |
| 힙한 | 개성있는·트렌디, 구조다름 | 정형 고딕 |
| 강렬한 | 힘있는, 굵은 | 가는 |
| 차분한 | 단정·섬세, 가는 | 굵은·매우 느슨 |

### 쓸 곳 → 제약
| 쓸 곳 | 규칙 |
|---|---|
| 간판·메뉴판 | 읽힘 3만 허용(읽힘 1 제외), 굵기 보통 이상 가산 |
| SNS·썸네일 | 개성·굵은 가산, 읽힘 2 이상 |
| 포장·스티커 | 굵은·둥근 가산 |
| 명함·인쇄물 | 가는·단정 가산, 읽힘 3 |
| 웹사이트·앱 | 정형·읽힘 3 가산 |

### 손맛(반듯하게 / 손으로 쓴 듯)
- 반듯하게: 느슨함 "정형·보통"에 +, "느슨·매우느슨"에 −.
- 손으로 쓴 듯: 느슨함 쪽에 +, 붓맛 폰트 허용.

### 안전장치
- 상위 5개 안에 한 묶음이 3개 넘으면 묶음별로 2개까지만 인정(다양성).
- 선택 후 30자 그림이 완성되면 무료 폰트·기존 서체와의 닮음 점수를 재고, 0.85에 가까우면 휨을 키우거나 다음 후보로 교체해 다시 그린다.
- 제작 기록에 선택된 폰트와 묶음을 남기되 사용자 화면에는 보이지 않는다.

## 4. 아직 안 된 것
- 점수표는 가설이다. 입력별로 실제 결과가 그 인상으로 나오는지 시험이 필요하다(예: "고급스러운" 입력 → 명조·무궁화 구조가 우아하게 나오는가).
- 읽힘 태그와 정형 쪽 다양성(고딕·명조 하위 구분)이 약하다.
- 구조 참고가 로고 분석 결과(속성)와 충돌할 때의 우선순위가 정해져 있지 않다.

## 5. 선택 규칙 시험 결과 (11/5, 바다식당 로고·속성 없음, 총 AI 약 $0.8)
스크립트 `web/scripts/gen-select-test.ts`, 자료 `docs/`가 아닌 scratchpad(select*-runs.jsonl).
- 1차(곰 얼굴 로고 + 둥글고 굵게 속성 남김): 세 입력이 모두 굵고 둥근 같은 글씨 → 시험 설계 실수(속성·로고가 묻음). 무효.
- 2차(속성 없음, 구조 참고 폰트만): 굵기·둥글기는 입력과 맞게 갈림(귀여움 성공). 칼국수체(가는 필기)를 뽑았는데 결과는 반듯한 가는 고딕 — 필기 구조 안 따라옴.
- 3차(구조 참고+구체 문장 vs 문장만, 입력 3×2):
  - 세 입력 모두 **세리프를 못 그림**. "전통 바탕체·명조" 문장을 줘도 고딕이 나옴. 구조 참고 유무와 상관없음.
  - 문장만 준 쪽(premium-text, trad-text)은 무료 폰트와의 최대 닮음이 **0.95, 0.94로 기준 0.85 초과**. 구조 참고를 준 쪽은 0.75, 0.82로 낮음(귀여운 쪽은 0.73/0.76으로 둘 다 낮음).
  - 구조 참고 폰트는 **중복 줄이기(닮음 낮추기)에는 효과**가 있으나 **분위기 표현(우아·전통)에는 효과가 없다**.
- 해석: 이미지 모델은 기준 글자표(고딕 뼈대)에 강하게 끌려 세리프·가는 필기 구조로 못 간다. 분위기를 폰트 선택으로 풀려는 A안 규칙은 굵기·둥글기 수준에서만 작동한다.

## 6. 구조 섞기 시험 (11/5, AI 호출 없음)
`engine/scripts/blend_proto.py`. 프로젝트 40개를 무작위 폰트 쌍으로 만들어 30자 뼈대를 비교한다. 지표: 프로젝트끼리 뼈대 닮음(낮을수록 다양), 풀 24종+무료 44종 중 가장 닮은 폰트와의 닮음(낮을수록 독창).

| 방식 | 프로젝트끼리 평균 | 가장 닮은 폰트와 평균 | 0.85 넘는 비율 | 글자 모양 |
|---|---|---|---|---|
| single (폰트 1개+휘기 0.6, 현재) | 0.366 | 0.771 | 5% | 정상 |
| pull (A 뼈대를 B 쪽으로 끌어당김) | 0.339 | 0.617 | 0% | **정상**(눈으로 확인) |
| blend (거리장으로 두 글자를 섞음) | 0.261 | 0.352 | 0% | **깨짐**(글·꽃·원이 알아볼 수 없음) |

- 거리장 섞기(blend)는 숫자가 가장 좋지만 글자가 끊기고 엉켜서 닮음이 낮아진 것이다. 숫자를 믿을 수 없다(처음 가는 획 그대로 섞었을 때는 획이 사라졌고, 굵기를 맞춰 섞으면 획이 뭉쳐 다시 깨졌다).
- 끌어당기기(pull)는 A의 획 연결을 유지해 읽힌다. 독창성은 0.15쯤 오르고, 프로젝트끼리 다양성은 0.03쯤만 오른다(24종 풀의 한계가 지배).
- 현재 방식(single)은 5%가 무료 폰트와 0.85 넘게 닮는다(정형 고딕이 뽑힌 경우로 추정).
- 한계: 40개 표본, 사람 눈으로 본 읽힘은 일부 글자 표본뿐. AI가 이 뼈대를 따라 그렸을 때 결과는 아직 모른다.
